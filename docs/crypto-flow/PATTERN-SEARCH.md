# Crypto 型態搜尋

First Crypto indicator tab. Drawing board and exactly two result columns at all supported widths. Two primary controls live inside the board: timeframe multi-select (4H + 1H default), and a searchable pattern library ordered by common use. Clear-last-stroke is a small board control. Cards show actual candles, matched path, symbol, timeframe, similarity, original OX score, 24h USDT turnover (萬 / 億), and 24h return. Tapping a result opens its 200-candle dataset with pan/pinch/wheel zoom.

## Source and scope

Bitget v3 instruments must explicitly identify crypto, perpetual, online, USDT. By default the canvas observes all active positive-turnover instruments; optional limits select the top 80 or 160 by turnover. The former 3 million USDT prefilter is removed. V2 tickers provide actual turnover, return and timestamps; V2 candles provide OHLC, base volume and quote turnover. Source requests ask for 200 bars, and may reuse a current native 180-bar response. Only valid, continuous, current observations survive. Missing volume is not converted into zero. The 6H/12H/1D/1W requests use official UTC variants.

The rate scheduler spaces new requests by 110ms with four in-flight symbol jobs, bounded retries, a 12-second request timeout and cancellation. Existing classic requests remain independently managed. Closed candles are cached until the next actual close boundary. Foreground preclassification starts immediately, before drawing. Refresh cadence is the smaller of five minutes and the shortest selected timeframe, checked every 15 seconds; close boundaries force fresh quotes. Requests stop in the background; rendering pauses. Unmount terminates the Worker. Failures are counted independently. No backend, key or paid data is required for this bounded public-API scan; a shared backend cache should replace per-user polling if concurrent usage grows.

Official endpoint definitions: https://www.bitget.com/docs/catalog/classic-contract-market/classic-contract-market and https://www.bitget.com/docs/catalog/market/market-data.

## Matching semantics

Price paths are normalized for price level/range and elapsed time. Forty samples are compared with DTW limited to seven sample positions, aligned absolute error and endpoint error. Similarity = 100 × clamp(1 − 2.2 × (0.55 × normalized DTW cost + 0.30 × aligned error + 0.15 × endpoint error)). This is a versioned geometric score, not a statistical confidence or success rate. No accuracy claim has been established by forward testing.

Named geometric patterns additionally require alternating pivots. Local extrema use symmetric radius/minimum-ATR-move pairs (1,.5), (2,.65), (3,1), (5,1.5), (8,2); outside bars with ambiguous high/low ordering are skipped. Candidate length is 16–161 bars and the ending pivot must be within the latest eight bars. For nonharmonic shapes, a final closed price can complete the visible path; it is not a promise of breakout. Shape similarity (60%) and actual close path similarity (40%) are combined. Geometric structures require >=77; W/M >=71; harmonic candidates >=72 plus all ratio gates. All pivot matches also require >=70 pivot-shape similarity. Custom paths scan 17–161 bar windows ending within six bars, with a >=70 score gate. Candidate windows and resampled paths are prepared once; aligned distance shortlists 16 windows before full DTW. No top-N padding if no matches.

W/M require similar troughs/peaks (<=25% of range), first leg >=35%, neckline depth >=30%, and second rebound >=18% of range. This includes forming candidates. Cards explicitly distinguish formation from a last close beyond the neckline; neither is a success claim. Head-and-shoulders require distinct heads and matching shoulders/necklines. Triangle/channel/wedge filters regress the high/low envelopes and test slope, convergence, expansion or parallelism. Flags/pennants additionally require an impulse leg. Generic cup/rounding/retest variants are explicitly path comparisons, not full textbook-pattern certification with volume or preceding trend requirements.

Harmonic targets additionally validate AB/XA, BC/AB, CD/BC, AD/XA and CD/AB where applicable. Fixed-ratio tolerance is relative ±5%; interval constraints are hard boundaries. Four-point AB=CD variants use their corresponding three ratios. Both directional variants are provided. This is independent code and original schematic drawing; no source diagrams or proprietary signal outputs are copied. Reference definitions: https://harmonictrader.com/harmonic-patterns/ (Gartley, Bat, Butterfly, Crab, Deep Crab, Alternate Bat, AB=CD).

Freehand strokes are mapped from canvas coordinates to elapsed-time/price direction. Two boundary strokes can form an alternating envelope query. A common pattern name is suggested above 78 geometric alignment (two boundaries: 83); the default query ALWAYS compares the actual sketch independently of that suggested name. A compact mode switch enables named structural criteria explicitly. A straight horizontal sketch selects horizontal resistance; a straight rising/falling sketch selects the corresponding trend line. Hand drawings are never labelled as harmonic by visual resemblance alone. The selected preset is always visible and replaceable.

The shared classic engine annotates each detected formation's confirmation. T1 requires full qualification; T2 and T3 retain partial confirmations or geometric formations marked “尚待量價確認”. Pattern discovery does not require full radar qualification and is not capped by radar's 15/15 groups. Valid levels still require independent rejected tests; consumed lines stay excluded. Similarity measures geometry; an unavailable classic score displays —. A canvas result never grants radar eligibility, and examples are not excluded by symbol name.

## Isolation and performance

Only `analytics/entry.js` and its URL in `index.html` change existing integration. The new module has a ShadowRoot and separate source cache. It does not write OX classic state, change ranking constants or add content to other markets. Math runs in a module Worker with a bounded main-thread fallback. Card canvases initialize on intersection; only 24 cards initially mount and more are requested in batches. Animations occur only on interaction and dialog opening/closing, using the radar timeframe easing and white selected edge; reduced-motion is honored. Chart/canvas listeners, observers, Workers, RAFs, timers and dialogs dispose on unmount.

## Verification

`node --test tests/crypto-patterns.test.mjs`: explicit synthetic positive/negative fixtures, ratio gates, W vs M and stale pattern rejection, missing/unclosed candle rejection, universe isolation and ranking.

`node scripts/test-crypto-patterns.cjs`: mobile/desktop UI using original recorded Bitget responses and the original capture time (never a fake current timestamp); preset filtering, default 4H/1H, two columns, OX adapter, freehand matching to a known real interval, pinch, navigation teardown and market isolation. Records are intercepted only in the test process.

`node scripts/validate-pattern-feed.mjs`: read-only live endpoint/CORS and closed-candle validation on all ten timeframes on the most liquid contract, plus three liquid contracts × the two default frames. GitHub Actions stores responses for audit, not as runtime fallback or a substitute for realtime access. Runtime remains direct browser REST.

## Preclassified index (v2)

51 entries: four new independent level/line categories, 29 conventional/path templates and 18 directional harmonic templates. Horizontal support/resistance and rising support/falling resistance trend lines appear above pattern families. Levels require at least two separated pivot touches, trend lines at least three; tolerance, violations, age and current-price distance are ATR bounded. The white overlay is the detected line. These can overlap named patterns and are not counted as aliases.

On page entry the Worker prepares each selected symbol/timeframe once, classifies all templates, and retains normalized candidate windows. Preset changes read this index synchronously with no market requests. Hand drawings search the existing prepared windows, also with no market requests. Query changes never cancel the independent data collector. Incoming series expand current results without restarting the scan. Counts use distinct symbols within the selected timeframes; one coin matching two timeframes counts once, and matching different categories is allowed. The menu shows collection progress; zero counts are ellipses while still loading.

IndexedDB version 7 persists real observations and classification outputs; current classifications render directly without worker reclassification on every visit. Previous versions may reuse current real candles and reclassify them once locally. The worker is prepared lazily when a drawing needs it. The blank board browses the selected universe independently of radar membership, and current native radar responses are reused before new candle downloads. Close boundaries invalidate observations; instrument eligibility is reapplied after metadata retrieval. A first visit or a new timeframe still loads market data incrementally.

The UI regression additionally asserts network activity before any sketch, zero new candle requests when changing a preset or drawing, menu counts matching displayed distinct coins, ten timeframe choices, and reload recovery while candle transport is blocked. Synthetic tests cover forming W, negative M, independent line overlap, cache invalidation, and preclassification parity.
